# Documentation review checklist

## Reader and purpose
- [ ] Audience and task are explicit.
- [ ] Document type matches the reader's need.
- [ ] Prerequisites, platform, versions, and permissions are stated.

## Accuracy
- [ ] Commands were checked against CLI help or source.
- [ ] Paths and filenames exist.
- [ ] Defaults and supported values are verified.
- [ ] API examples match current schemas.
- [ ] Compatibility claims cite official documentation.
- [ ] Facts, assumptions, and recommendations are distinguishable.

## Usability
- [ ] Reader can follow steps in order.
- [ ] Expected output and failure recovery are described.
- [ ] Destructive or externally visible actions are clearly warned.
- [ ] Examples use safe placeholders and valid formatting.
- [ ] Headings, tables, lists, and code blocks improve scanning.

## Maintenance and safety
- [ ] Relative links and anchors work.
- [ ] No secrets, private URLs, or personal data.
- [ ] Duplicated instructions link to a canonical source.
- [ ] Version-sensitive facts have a date/version note.
- [ ] Related docs/changelog are updated.
