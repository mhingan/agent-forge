# Accessibility and inclusive interaction rules

- Prefer semantic HTML and native controls; use ARIA only when native semantics are insufficient.
- Every control has a meaningful accessible name, correct role/state, and visible focus.
- All functionality is keyboard-operable with logical focus order and no keyboard traps.
- Dialogs manage focus entry, containment, Escape behavior, and focus restoration.
- Every form control has a label; errors and help text are programmatically associated.
- Do not rely on color, hover, placeholder text, or icon alone to convey meaning.
- Support zoom, text scaling, contrast modes, reduced motion, and narrow viewports.
- Announce important asynchronous status without flooding screen readers.
- Give informative images and charts accessible alternatives; caption/transcribe media when required.
- Automated scans are not a substitute for manual keyboard and assistive-technology testing.
