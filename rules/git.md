# Git and collaboration rules

- Inspect `git status`, current branch, and diff before changing or staging files.
- Do not overwrite unrelated user changes or reset files without explicit approval.
- Keep commits focused and messages descriptive.
- Do not commit generated secrets, credentials, private datasets, build artifacts, or local environment files.
- Never force-push, rewrite shared history, delete branches, or create releases without explicit authorization.
- Review the staged diff before committing.
- Reference tests and behavior changes in pull-request descriptions.
