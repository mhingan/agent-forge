# Plan a feature before implementation

## Purpose
Translate a request into a scoped implementation plan with testable outcomes.

## Procedure
1. Identify user, problem, desired outcome, and evidence.
2. Inspect current architecture, relevant code, contracts, data model, and design patterns.
3. State requirements, non-goals, assumptions, and open questions.
4. Map user journey, roles/permissions, data, state transitions, error/recovery states, and side effects.
5. Identify API/schema/configuration/UI/deployment/documentation impact.
6. Break implementation into small reviewable steps.
7. Define tests and acceptance criteria for each step.
8. Identify security, privacy, accessibility, compatibility, migration, and operational risks.
9. Present alternatives only where they change a meaningful trade-off.

## Output
Problem/outcome; current-state findings; scope/non-goals; implementation steps; affected files/contracts; acceptance criteria; test plan; risks/dependencies; rollout/rollback; open decisions.

## Boundaries
Do not begin implementation unless asked. Do not invent missing product requirements, timelines, or capacity estimates.
